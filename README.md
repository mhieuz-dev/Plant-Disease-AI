# Plant Disease AI

Research prototype for plant disease diagnosis and advisory for coffee, rice, and black pepper in Vietnam. A leaf image is classified by a MobileViT-S model, the decision is explained with a Grad-CAM heatmap, and management advice is generated by GPT-4.1-mini from crop-specific documents retrieved with retrieval-augmented generation (RAG). The server is consumed by a mobile client, which is not part of this repository.

This repository accompanies the manuscript "An Intelligent Plant Disease Diagnosis and Advisory System Integrating Mobile Vision Transformers, Explainable AI and Retrieval-Augmented Generation" by Hieu Ho, Nam Nguyen, and Bao Nguyen (Institute of Intelligent and Interactive Technologies, University of Economics Ho Chi Minh City), currently under review.

**Disclaimer.** This is a research prototype that has not been validated in the field. Its advice, in particular product names and doses, must be confirmed with a plant protection officer and the product label before use.

## Disease classes

| Crop | Class labels |
|------|--------------|
| Coffee | `cafe_Leaf rust`, `cafe_Miner`, `cafe_Phoma`, `cafe_Healthy` |
| Rice | `rice_Leaf Blast`, `rice_Leaf scald`, `rice_Sheath Blight`, `rice_Healthy Rice Leaf` |
| Black pepper | `tieu_Footrot`, `tieu_Pollu_Disease`, `tieu_Slow-Decline`, `tieu_Healthy` |

## System overview

1. `POST /detect` receives a leaf image, checks with GPT-4.1-mini that it shows a plant, classifies it with MobileViT-S, computes a Grad-CAM heatmap, and returns the diagnosis, the heatmap, and an advisory answer.
2. `POST /chat` and `POST /chat/stream` (server-sent events) answer follow-up questions in the same conversation. For a diseased class, passages are retrieved from the FAISS index of the crop and given to the model, and the answer cites them.
3. Documents in `docs/<crop>/` are split into chunks of 800 characters with an overlap of 100, embedded with OpenAI `text-embedding-3-small`, and stored in one FAISS index per crop (`ca_phe`, `lua`, `tieu`). The indexes are built, or loaded if they already exist, when the server starts.

## Advisory safeguards

The revised prototype adds three safeguards to the advisory module. They are enabled by default and can be disabled with `SAFEGUARDS=0` to reproduce the original behaviour.

1. **Disease-scoped retrieval.** Each document is tagged with the diseases it covers (`data/disease_tags.json`). The 100 nearest chunks are re-ranked so that chunks from documents about the diagnosed disease come first, and, for questions about products or doses, chunks that name a pesticide come first among them. Six chunks are used. Lines that name a product that is banned or no longer registered in Vietnam are removed before the passages reach the model. Citations show a readable document title (`data/docs_meta.json`).
2. **Grounding rules.** The prompt instructs the model to name products, active ingredients, doses, and spray schedules only when they occur in the passages, to cite the passage after each recommendation, and to refer the user to a plant protection officer when the passages do not cover the question. Answers are generated at temperature 0.2 instead of 0.7.
3. **Post-generation check.** Every active ingredient and trade name in the answer is matched against the Vietnamese list of registered pesticides (Circular 75/2025/TT-BNNMT as amended by Circular 28/2026/TT-BNNMT, stored in `data/pesticide_registry_vn.json`) and against the retrieved passages. Banned or deregistered products are redacted together with their dose, and products or doses that are not supported by the passages or not registered for the crop are flagged in the answer.

The implementation is in `services/safeguards.py` and `app.py`. The check does not verify doses against the registry and depends on the lexicon recognising the product name as written.

## Repository structure

| Path | Content |
|------|---------|
| `app.py` | FastAPI server and endpoints |
| `models/predict.py` | MobileViT-S inference |
| `services/gradcam_service.py` | Grad-CAM heatmap, bounding box, and affected-area estimate |
| `services/rag_service.py` | Document loading, FAISS indexing, retrieval, and prompt construction |
| `services/chatgpt_service.py` | Image validation and advisory generation with GPT-4.1-mini |
| `services/safeguards.py` | Advisory safeguards |
| `data/` | Disease tags, document titles, and the pesticide registry used by the safeguards |
| `docs/` | Advisory corpus, one folder per crop |
| `tests/test_rag.py`, `tests/test_vanilla.py` | Scripts that submit the 20 evaluation questions with and without retrieval |
| `scripts/evaluate_postprocessing.py` | Evaluation of the colour-based leaf miner and leaf rust post-processing rule |
| `images/` | Example Grad-CAM figures |

## Installation

Requirements: Python 3.10 or later, an OpenAI API key, and the model weights `best_mobilevit.pth`. The weights are not included in the repository and are available from the corresponding author upon reasonable request.

```bash
python -m venv .venv
source .venv/bin/activate
pip install fastapi uvicorn python-multipart python-dotenv pydantic \
    torch torchvision timm pillow numpy openai requests \
    langchain-core langchain-community langchain-openai langchain-text-splitters \
    faiss-cpu pypdf
cp .env.example .env
```

Set `OPENAI_API_KEY` and a private `ADMIN_SECRET` in `.env`, and place `best_mobilevit.pth` in the repository root.

## Usage

```bash
uvicorn app:app --host 0.0.0.0 --port 8000
```

| Method | Endpoint | Purpose |
|--------|----------|---------|
| POST | `/conversation/new` | Create a conversation |
| POST | `/detect` | Diagnose an uploaded leaf image (`file`, optional `conversation_id`) |
| POST | `/chat` | Answer a follow-up question (`conversation_id`, `question`) |
| POST | `/chat/stream` | Same as `/chat`, streamed as server-sent events |
| DELETE | `/conversation/{cid}` | Delete a conversation |
| POST | `/admin/rebuild-indexes?secret=...` | Rebuild the FAISS indexes after changing `docs/` |
| GET | `/health` | Server status |

With the server running, `python tests/test_rag.py` and `python tests/test_vanilla.py` submit the evaluation questions with and without retrieval and write the answers to `rag_results.json` and `vanilla_results.json`. On Windows, set `PYTHONIOENCODING=utf-8` first.

## Main results

The following results are reported in the manuscript.

| Evaluation | Result |
|------------|--------|
| MobileViT-S, original data partition | 88.33% test accuracy |
| MobileViT-S, EfficientNetV2-S, MobileNetV3-Large, ResNet-50, leakage-controlled partition | 98.2 to 98.8% mean test accuracy over three seeds, no consistent difference |
| MobileViT-S inference cost | 67 ms per image on one CPU thread |
| Answers recommending a pesticide no longer registered in Vietnam (20 questions, three generations) | LLM only 25%, RAG as deployed 20%, RAG with safeguards 3 of 60 answers |

An audit of the merged public dataset found that 37.3% of the test images in the original partition were byte-identical to training images and that the 300 test images labelled coffee leaf miner are Cercospora leaf spot images in their source dataset. The manuscript describes the audit, the evaluation protocols, and the limitations in full.

## Data sources

The images come from public datasets cited in the manuscript and are not redistributed here. The documents in `docs/` are publications and extension materials from their respective authors and publishers, collected for research use. The pesticide registry in `data/` was compiled from Circulars 75/2025/TT-BNNMT and 28/2026/TT-BNNMT of the Ministry of Agriculture and Environment of Vietnam.
